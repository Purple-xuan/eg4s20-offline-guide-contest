# EG4S20 离线交互式导览终端——作品提交源码

目标器件：安路 EG4S20BG256。开发工具：Tang Dynasty（TD）6.2.168116。顶层模块：`top`。
本包采用布局种子（seed）50，为已由项目作者完成板级功能验证的时序正裕量版本。
RTL、IP 和头文件与已验证源码快照逐字节一致；工程整理仅调整了目录结构及 TD 工程中的文件引用路径。

## 工程目录

| 路径 | 内容 |
| --- | --- |
| `src/top`、`src/common`、`src/control` | 顶层集成、时钟与复位辅助、输入处理及导航控制 |
| `src/storage`、`src/filesystem`、`src/memory` | SD 卡与 FAT32 文件系统、SDRAM、行缓存及常驻图像传输 |
| `src/image`、`src/video`、`src/osd` | 图像解码、画面显示、转场及屏幕叠加显示 |
| `src/audio`、`src/hdmi`、`src/ip`、`src/include` | 音频、HDMI、厂商 IP 及公共定义 |
| `prj`、`constraints` | 可迁移的 TD 工程、原始引脚约束（ADC）与时序约束（SDC）、实现阶段裕量约束 |
| `sim`、`scripts` | ModelSim 回归仿真及 TD 构建、检查脚本 |
| `bitstream`、`implementation`、`reports` | 已签核位流、布线后数据库及工具报告 |
| `touch_panel`、`assets/TF` | 触摸屏工程及 FAT32 存储卡参考素材 |

## 打开工程与使用位流

请将工程解压或克隆到纯英文路径，避免 TD 命令行工具的中文路径编码问题。

在 TD 中打开 `prj/official_example.al`。原始时序约束位于 `prj/official_example.sdc`。
可直接使用的位流为 `bitstream/official_example.bit`。

## 文件校验与构建

在工程包根目录执行下列命令，核验文件哈希、工程引用及头文件引用：

```powershell
python scripts/verify_package.py
```

在工程包根目录执行下列命令，进行设计展开检查：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run.ps1 -Mode check
```

如需从源码完整重建，依次运行 `synthesis`（综合）、`route`（布局布线）和
`rebuilt_bitgen`（从重建结果生成位流）模式。
`bitgen` 模式使用包内已有的布线后数据库重新生成位流。
位流生成前，脚本会使用原始 SDC 检查建立与保持时序裕量，要求均不为负。

## 回归仿真

ModelSim 回归仿真入口如下：

| 仿真入口 | 验证内容 |
| --- | --- |
| `sim/run_display.do` | 常驻图像显示引擎综合回归 |
| `sim/run_return.do` | 返回转场回归 |
| `sim/run_normal_wipe.do` | 普通擦除转场回归 |

在工程包根目录执行 `vsim -c -do <script>`，将 `<script>` 替换为对应入口路径。

## 时序签核与版本记录

本包位流已完成布线后慢角与快角（Slow/Fast）静态时序分析。
已约束路径的建立时间最差裕量（Setup WNS）为 +0.374 ns，
保持时间最差裕量（Hold WNS）为 +0.022 ns，静态时序分析覆盖率为 99.97%。
版本信息、文件哈希及源码路径对应关系记录在 `release.json` 和 `source_manifest.csv` 中。
从源码完整重建可能改变布局布线结果，重建后需重新检查时序。
